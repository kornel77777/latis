# M7 QA: performance and security pass (2026-10-26)

Measured on an Apple Silicon MacBook from `out/` (the e2e build), Electron 45.

## Performance (SPEC §14)

| Budget                                                       | Result                                                                                                                                                                                            |                  |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Cold start → interactive, < 2.5 s                            | 0.55–0.59 s (4 launches, lattice default)                                                                                                                                                         | ✅               |
| Pan/zoom with 50 nodes, 10 streaming chats: no frame > 32 ms | p95 9.2 ms, max 9.4 ms, 0 over 32 ms at 100% and zoomed out (`LATTIZ_PERF=1 e2e/perf.spec.ts`)                                                                                                    | ✅               |
| Idle CPU with 10 idle chats, < 2%                            | 0.03% (was about 2% before the fix below)                                                                                                                                                         | ✅               |
| Memory, < 600 MB base                                        | 520 MB with 10 idle chats on the canvas; 620 MB on an empty lattice, summing every process's working set, which counts shared frameworks more than once. Main process: 219 MB RSS, 44 MB JS heap. | ⚠️ near the line |
| Agent event → pixels, 2,000-turn transcript, 5,000-line diff | Not re-measured in this pass                                                                                                                                                                      | —                |

**Fixed:** the status bar's "working" and "needs you" dots pulsed forever, even at zero. Two endless CSS animations kept the renderer and GPU at about 2% CPU on an empty window. `StatusDot` now takes `still`, the status bar uses it for counts of zero, and `e2e/data.spec.ts` checks that an idle window runs no animations.

**Open:**

- **Renderer bundle:** the main chunk is 3.2 MB (1.6 MB at M1), and the Shiki highlight worker is 1.5 MB. Start time is still well within budget, but splitting xterm and the flow editor into lazy chunks would help memory.
- **Memory:** should be measured on a packaged build and on Windows.

**Accepted risks:**

- **The user's own processes:** the always-ask list stops agents through their own hook and approval mechanisms. A process running as the user can still read Lattiz's run files or change an agent's own settings. Lattiz doesn't defend against the user's own account.
- **Terminal agents:** apart from Claude Code, they aren't covered by the always-ask list. The chat header says so.
